# Ubuntu 24.04 user-lifecycle smoke test — 2026-08-24

This smoke test exercised the source-tree user installer on Ubuntu 24.04.4,
GNOME/X11, systemd user services, and IBus 1.5.29. It used an existing desktop
user, not a fresh VM, so it does not close the clean-machine release gate.

No API key, microphone audio, transcript, vocabulary term, or Rime user data
was read or recorded during this test. The new standalone voice service had no
configuration and therefore remained disabled and inactive.

## Verified sequence

1. Installed with the explicit developer-network flag. The managed venv
   installed `murmur-ime-voice` 0.1.0, `sounddevice` 0.5.6, `websockets`
   17.0.1, and their isolated transitive dependencies.
2. Verified the engine unit was enabled and active, the voice unit was
   installed but disabled/inactive, and `pip check` reported no broken
   requirements with user site-packages disabled.
3. Re-ran the installer as an upgrade. The engine service received a new PID,
   and the previously active `libpinyin` IBus engine was restored after dynamic
   component restart.
4. Validated both generated units with `systemd-analyze --user verify`.
5. Uninstalled. Both units and the complete project-owned install root were
   removed, while `libpinyin` remained active and the existing
   `~/.config/ibus/rime` directory remained present.
6. Reinstalled and repeated the unit, venv, IBus-engine, and service-state
   checks. The compatibility Flatpak remained able to run alongside the idle,
   disabled standalone daemon.
7. Built and inspected a clean wheel: licence and notice files were present;
   no `__pycache__` directory or `.pyc` file was packaged.

## Still required
